## 3. View tab — current state (web canonical)

The **View** tab is `web/src/components/ViewPanel.tsx` (the old `TimelineViewPanel.tsx`
referenced in CLAUDE.md no longer exists). It is the interactive review surface: file +
type dropdowns, filtered-usage toggle, highlight-app search, TIMELINE / APP LISTS subtabs,
A/B compare, a participant rail, and per-day metrics. It is **widescreen** (`.app-shell--wide`)
while staying horizontally aligned with the other tabs.

Two UX regressions were fixed in **#71**:

- **File search+dropdown** (`web/src/components/Combobox.tsx`). The combobox filtered its
  option list by the input's *current value*, so once a file was committed (the value became
  the full filename) reopening the popup filtered the list down to just that one file. Fix:
  an **`isEditing` flag** — the list filters **only while the user is actively typing**; a
  fresh focus (showing a committed selection) lists **every** option, and the highlighted row
  tracks the current value so Enter re-commits it. This combobox is shared with the timezone
  selector (`TimezoneCard.tsx`), which gets the same improvement.
- **Compare ("Arm B") settings drawer** (`web/src/components/review/CompareConfigDrawer.tsx`
  + `web/src/index.css`). Four full settings cards were crammed into a narrow
  `auto-fill minmax(280px)` grid, so the overview card's own internal 2-col grid overflowed
  and overlapped. Fix: lay the drawer out **exactly like the Settings tab** — overview
  full-width on top, the three detection cards in the shared `.settings-stack` 2-col grid
  (interaction-semantics keeps its full-width row), with `minmax(0,1fr)` on `.review-drawer__body`
  so the nested grid can't blow out at intermediate widths.

The widescreen mechanism itself (don't regress it): `.app-shell--wide` is `width: 100%`,
and the hero / workflow-nav / footer are re-inset with `width: min(1360px, calc(100% - var(--space-5)))`
+ `margin-inline: auto`, while `#workflow-panels` is full width. Capping `.app-shell--wide`
to a fixed width (as PR #59 did) both narrows the View *and* shifts the chrome right.

## 4. Python usage-window paradigm — what landed (PR #73)

Background: the **web surface already shipped** no-activity placeholder days + intra-app
proximity (PR #68, web-first). PR #73 brings the **Python desktop** in line so the two
surfaces match. Everything is **parity-safe**: the deterministic fixture has neither study
dates nor proximity, so the cross-surface gate stays byte-identical (verified: 0 mismatches).

In `src/chronicle_preprocessing_app/core/preprocessing/polars_fast_path.py` (+ `config.py`,
`main_preprocessor.py`, `timestamp_preprocessor.py`, `screen_usage_preprocessor.py`):

- **`proximity_interval_seconds`** (new `PreprocessingOptions` field, default `0.0` = off).
  When `> 0`, an Activity-Stopped *fallback* close landing within the window of a **re-resumed**
  session start is treated as an intra-app teardown artifact, not a real close — the session
  stays open. Implemented **only in the Python matcher** (the Rust matcher has no proximity
  parameter), so `proximity > 0` forces the Python matcher path. `proximity == 0` is
  byte-identical to before.
- **No-activity placeholder rows** (`com.placeholder.noactivity`, 0 duration) for study-range
  days that have raw data but no app usage. Only active when a `study_date_provider` is
  available; the fast path now supports the date provider (dropped from its "unsupported" gate).
- **Fractional-second timestamps** (`%.f` formats tried first, in both the fast path and the
  legacy `timestamp_preprocessor`). Chronicle carries millisecond precision; silently nulling
  it segmented real sessions to ~0. Whole-second strings fall through unchanged.
- **Legacy interaction-type canonicalization** + `infer_schema_length=None` schema fix
  (alternate-vocabulary devices, late-appearing string columns).

The **consumer's locked config** and the **not-yet-built** paradigm pieces are documented in
`CLAUDE.md` §"Usage-window semantics (research-pipeline consumer)". See §6 below.

## 5. CI / workflows — now green, what was broken

PR #72 ("Canonical-config baseline") re-introduced **remote** GitHub Actions (a `security`
workflow) and added eslint tooling, but left several configs broken — turning `main` red.
PR #74 fixed all of it. Things to know:

- **Remote CI is back.** `.github/workflows/`: `security.yml` (gitleaks + osv-scanner, on
  push & PR) and `web-pwa-deploy.yml` (build + deploy to Pages on push to `main`, no tests).
  There's also an external **semgrep-cloud-platform** check and **CodeRabbit** on PRs. The
  authoritative gate is still **local `make all`** — but the remote checks now also pass and
  should be kept green.
- **Web PWA deploy `npm ci`** failed because #72 added `eslint`/`@typescript-eslint` to
  `web/package.json` without regenerating `web/package-lock.json`. Fixed by regenerating the
  lockfile. (If you add web deps, always commit the updated lockfile or the deploy breaks.)
- **osv-scanner** must be called as a **reusable workflow** (`google/osv-scanner-action/.github/workflows/osv-scanner-reusable.yml@v2.3.8`),
  not a step action — that repo ships no root composite action and has no `v1`/`v2` moving tag.
- **gitleaks-action** needs `env: GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}` to scan
  `pull_request` events (passes on push without it).
- **osv-scanner gates on vulns** (`fail-on-vuln` defaults true) and reads pinned versions from
  `requirements.txt`, so it catches things the local `make` pip-audit (which audits the
  *installed venv*) does not. This session it surfaced 10 real CVEs; fixed by pinning
  `pillow>=12.2.0` / `pygments>=2.20.0` (unpinned transitives; floors match the runtime) and
  bumping `memmap2 0.9.10 → 0.9.11` in `rust/chronicle_polars_kernels_wasm/Cargo.lock`
  (RUSTSEC-2026-0186). Note: that wasm pkg is prebuilt/committed and was **not** rebuilt — only
  its `Cargo.lock` was updated for the scanner. Rebuild it (`npm run build:wasm` + `git add -f`)
  if you touch that crate for real.

## 6. Open / not-yet-built (deliberately deferred)

The **valid-usage-window paradigm** the research-pipeline consumer decided on is only
**partially** built. Still to do (design **web-first**, keep parity-safe / default no-op on
the fixture) — see `CLAUDE.md` §"Usage-window semantics" and the consumer's
`docs/chronicle-decisions-made.md` §14:

1. **Screen-Non-Interactive as a session closer** with a **blip-bridge** (an off shorter than
   the 2-min auto-lock followed by the same app within 2 min is bridged, not a close). Today
   Screen Interactive/Non-Interactive feed only `screen_usage_preprocessor.py`, never the
   matcher — so screen-off does **not** close an app-usage session.
2. **Truncate-to-6h** instead of zero-out for the long-duration cap (keep the first 6 h). Today
   a >threshold session is zeroed via End-of-Usage-Missing, not truncated.
3. **No-true-end** (runs to shutdown/death with no screen-off) → credit screen-on to the last
   engagement, not a blanket zero.

Also: `proximity_interval_seconds` and the placeholder-days option exist in both surfaces but
are **default-off**; if they should be surfaced/locked for the consumer, wire defaults via the
**LinkML contract** (`web/schema/chronicle-local-contract.linkml.yaml` → `npm run check:contract`),
not the generated file.
