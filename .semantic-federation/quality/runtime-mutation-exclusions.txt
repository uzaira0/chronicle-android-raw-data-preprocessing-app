# cargo-mutants exclusions for rust/chronicle_preprocessing_runtime_wasm.
#
# One expression per line, matched against the mutant names `cargo mutants
# --list` prints (`path:line:col: description`). Blank lines and '#' comments
# are ignored. Every expression below matches at least one surviving mutant and
# no mutant the suite kills, and `check-rust-quality.sh mutation` now proves
# both before the campaign: it lists the crate's mutants, fails on any
# expression matching zero of them, and runs the excluded mutants themselves
# (`-F` selects exactly what `-E` removes), failing on any that is caught.
#
# The expressions are anchored on the mutation's column, description and
# function, not on its line. A line anchor rots on every merge that inserts
# code above it: this file shipped twelve line-anchored expressions and the
# integration merge left five of them — the `execute_incremental_pipeline`,
# `source_scopes` (x2), `state_for` and `execute_prepared_workspace` entries —
# matching nothing, silently returning the seven mutants they justify to the
# gate as misses. A column is stable under insertion above; where two mutants
# share a column, description and function, the expression carries the line
# and says why.
#
# This crate's mutation gate had never run before 2026-08-02: its entry in
# rust-authority-manifests.txt carried an inline alternation, the loader splits
# an entry on '|' and its exclusion field on ',', and cargo-mutants rejected
# the truncated regex before testing anything. The exclusion set that entry
# meant to carry was also far broader than its survivors — the single
# expression `src/lib\.rs:[0-9]+:1[37]: replace && with` matched 11 mutants of
# which only 3 survive; the other 8 are caught, and blanket-excluding them
# would have let a future regression in dependency_evidence_current,
# execute_incremental_pipeline and build_correspondence_index pass silently.
# They are tested again.

# --- A precondition its callers already enforce ----------------------------
# `if !verified_persisted_input || owned_review_csv.is_some() ||
# !verified_review_base.is_empty() || !verified_reconstruction_base.is_empty()`
# guards the warm-review branch of execute_incremental_pipeline. Every
# disjunct is false whenever that branch is entered, so `||` and `&&` both
# never fire. The only caller that passes warm_verified_input = true is
# PreparedReviewWorkspace::execute_selected_base_native, which forces
# selection = None (so both bases are empty), rejects a non-empty selected
# base outright, and takes the raw-fallback branch only when
# !warm_verified_input (so owned_review_csv is None and
# verified_persisted_input is true). execute_workspace_native_with_review_bases
# passes false and never reaches the branch.
:21: replace \|\| with && in execute_incremental_pipeline$

# --- Source scopes the product cannot produce ------------------------------
# `source.role_id == "processing_options" && source.coordinate_media_type ==
# "application/json"` reads as two conditions but is one: every CanonicalSource
# the runtime builds sets coordinate_media_type to a literal, and
# "application/json" appears at exactly one construction site, the one whose
# role_id is the literal "processing_options". Every other site, including all
# support roles, is "text/csv". No source can satisfy one condition without the
# other, so `&&` and `||` select the same sources.

# always a JSON object. The Array arm exists so a top-level array would still
# yield index selectors rather than panic; the product never emits one, so
# deleting the arm cannot change a scope the runtime computes.
