## Cause of the two failing narrow-viewport e2e tests (confirmed in the rendered app)

Both `e2e/app.spec.ts:799` (320x900, Settings/Files/Process) and `e2e/persona-adversary.spec.ts:108` (320x400, Settings/Files/Process/View) fail on the **Settings** tab, which is also the landing tab. The document is 326 px wide in a 320 px viewport. The only offending element is the hint `<span class="text-faint u-meta-xs">.csv only · columns: participant_id, modality_scope, availability_state, year_equivalent_exposure_numerator, year_equivalent_exposure_denominator</span>`, measured at left 101 and right 326, width 225 px.
- Where it comes from: the "Call/SMS eligibility" row, `src/components/StudyInputsCard.tsx:224-226` (columnsHint), rendered at `:360-363`.
- How it overflows: the hint sits in `.u-inline-cluster`, a flex row with no wrap (`src/index.css:3031-3035`), next to the title. That row is inside `.support-file-row`, whose `grid-template-columns: 1fr auto` (`src/index.css:3043-3045`) has a minimum of `auto`. The unbreakable token `year_equivalent_exposure_denominator` is about 225 px, so it forces the min-content width past the viewport.
- What is clean: every other tab, and the View and Process tabs after a real processing run, measure doc == viewport at 320, 360 and 390.
