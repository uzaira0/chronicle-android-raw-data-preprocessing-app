## Things learned the hard way

### Dependency evidence: 2 workers at 12 GB

With 4 campaign workers at `CAP_MEM=12G`, the run was killed for running out of memory
(exit 143). Two workers passed:

```
CHRONICLE_NIGHTLY_TOOLCHAIN=nightly-2026-04-23 RUSTUP_TOOLCHAIN=1.97.1 \
CHRONICLE_CAMPAIGN_WORKERS=2 CAP_MEM=12G CAP_CPU=800% cap make dependency-evidence
```

`cap` now refuses to start (exit 75) when the box is low on memory, instead of starting
anyway. That change followed the 2026-10-20 freeze, when four heavy jobs from three sessions
ran at once. Check free memory before any heavy job, and run one at a time.

### A new intervention kind moves published figures in five docs

#127 added two intervention kinds to the artifact campaign. `check-execution-claims.py`
then failed until the new changed-cell totals were written into `README.md`,
`web/combinatorial/README.md` and three files under `docs/semantic-federation/`. After
that, `make pin-figures` fixed the remaining drift: mutant counts and WASM sizes. Update
the docs first, then pin.

### Vite advisories when `npm update` crashes

osv-scan on #127 failed on new vite advisories. `npx npm@10 update vite --package-lock-only`
crashed ("Cannot read properties of null (reading 'edgesOut')"), so vite 7.3.5 → 7.3.7 was
edited by hand in `web/package-lock.json` and `web/bun.lock`: version, `resolved`,
`integrity`, and the esbuild peer range. Verify a hand edit three ways:

- `scripts/check-npm-lockfile.sh`
- a real `npm@10 ci`
- `bun install --frozen-lockfile`

Stay on vite 7. The esbuild override already clears the vite 8 advisories.

### Verifying a production deploy

The `index-*.js` hash never matches a local build, because the build stamp differs. Check
these instead:

1. The deployments API lists the new SHA first.
2. The live `asset-manifest.json` names match the local build.
3. The runtime WASM, the semantic index WASM and the codebook files are byte-identical to
   the repo.
4. A dispatched `canary.yml` run passes.

### WebKit on deni

WebKit cannot launch on this host because system libraries (libicu74 and others) are
missing. Judge e2e on Chromium and Firefox; all 37 WebKit tests fail at launch.
