cargo mutants \

## Classification

Every one of the 175 is in exactly one class. There are no unclassified entries
and no `accepted` entries: each is either killed by a test written in this
campaign, or excluded with a written reason in
`.semantic-federation/quality/kernel-mutation-exclusions.txt`, which the
mutation gate loads.

12 of the 175 are the sweep's timeouts; the thirteenth expression in the
loop-counter class covers a sibling that misses rather than hangs. The
`src/bin/` expression matches no survivor because the sweep already excluded
that path — it is carried so the gate's own invocation keeps excluding it.

The full reason for each class, and the tests that pin the invariant making it
equivalent, are written above the expressions in
`.semantic-federation/quality/kernel-mutation-exclusions.txt`. Each expression
was checked against `cargo mutants --list`: it matches at least one surviving
mutant and **no** mutant the suite kills. Four carry a line number, because the
three review-cone helpers each hold several `if !...` guards at the same column
and only some are equivalent; a drifted line number is loud rather than silent,
because the mutant it stops matching returns as a missed mutant and fails the
gate.

The two largest classes are the review cone. A review run produces one product
artifact, the summary, and `build_review_summary` reads only identity, date,
duration, package, label, category, interaction type, timestamps and usage
layer. Within that cone a `PartialEq` that reports "changed" for an unchanged
value costs reuse and never correctness — Salsa recomputes and gets the same
value back. The opposite direction, an equality too permissive to notice a real
edit, is a defect, and it is caught: every `&&` → `||` in those implementations
fails the suite except in `ReviewUsageRowsBeforeFloor` and `ReviewAnnotations`,
whose consumers re-verify row identity and copy durations from the upstream
table before using them.

## Two defects found outside the mutant list

The gate could not run at all, and finishing this campaign meant fixing that.

1. **Two crates' mutation gates had never started.** A manifest entry in
   `.semantic-federation/quality/rust-authority-manifests.txt` is split on `|`
   and its exclusion field on `,`, so an expression containing either was cut in
   half. The runtime crate's `(physical_data_row_count|duplicate_safe_headers)`
   and the matcher's whole function alternation both did, and cargo-mutants
   rejected the unclosed group before testing anything. The matcher's coverage
   ratchet was reading a fragment of that regex as its line threshold. Both are
   now written as separate expressions matching exactly the same mutants, the
   loader rejects an inline expression containing `(` or `{`, and an expression
   set that needs grouping lives in its own `@file`.

2. **Test-only code was hashed into the production implementation digest.**
   `rust/chronicle_preprocessing_runtime_wasm/build.rs::is_test_only` decided a
   module was test-only by checking whether its token stream *starts with*
   `#[cfg(test)]`. A doc comment is an attribute, so a documented
   `#[cfg(test)]` module was hashed as production source — the kernel's
   `output_contract` and `golden` modules both are. Every edit to those test
   modules moved `CHRONICLE_IMPLEMENTATION_BUILD_DIGEST`, which
   `dependency_evidence_current` compares against the embedded dependency
   certificate; a mismatch fails closed, and the runtime crate's warm-reuse
   tests then see every step recomputed. Bisected to `405ed69`, whose only
   non-test change was adding a doc comment above a `#[cfg(test)] mod`.
   `is_test_only` now reads an item's attributes with `syn` regardless of
   order, so a test-only edit no longer moves the digest.
