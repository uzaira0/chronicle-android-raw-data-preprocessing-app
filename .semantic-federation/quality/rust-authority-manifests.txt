# Product-owned crates that carry semantic/computational authority.
# The adapter's cfg(wasm)-only facade is target-incompatible with native
# cargo-mutants; its delegate is unit-tested and its export is browser-tested.
# Multiple exact inline exclusion expressions are comma-separated, and the
# entry's own fields are '|'-separated, so an inline expression can contain
# neither character: a regex carrying one is split in half and cargo-mutants
# rejects the unclosed group. The runtime and matcher entries each shipped
# such a regex and their mutation gate could not start; both are now written
# as separate expressions, which match exactly the same mutants.
# The kernel's contract-export binary is exercised by the contract drift gate;
# cargo test cannot call its `main` in a mutant sandbox. The matcher's optional
# Python-only facade is outside the browser product and creates 703,742 bogus
# tuple-return mutants; its Rust core remains fully in scope.
# Optional fields after the exclusion regex ratchet line, region, and function
# coverage for an established authority below the shared new-code defaults.
# The final field lists product features required by both coverage and mutation;
# omitting `incremental-v2` would silently test the retired non-authoritative
# kernel build instead of the production 55-step query engine.
# A seventh `no-default-features` field keeps a gate on the exact feature set
# linked into the browser when a crate's defaults only expose another product.
#
# The kernel's and runtime's exclusion sets are too large and too regex-heavy
# for the inline field, so they name a file instead:
# @kernel-mutation-exclusions.txt and @runtime-mutation-exclusions.txt, one
# expression per line, grouped under the reason each class is equivalent. Such
# a file is also the only place an expression may contain a ',' or a '|'.
#
