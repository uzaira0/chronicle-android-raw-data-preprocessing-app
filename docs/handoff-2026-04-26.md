## Current UI Structure

### Top-Level Layout

- Hero with title, lede, and the demo sample card.
- Workflow tabs below hero:
  - `Settings`
  - `Files`
  - `Process`
- Current tab buttons include subtitle/meta lines. This makes the tabs tall and visually uneven.

### Settings Tab

Current order:

1. Settings header with search.
2. Settings search results.
3. Presets manager.
4. Settings overview card.
5. Collapsible settings cards:
   - Support files
   - Timezone
   - Session detection
   - Screen detection
   - Interaction semantics
   - Performance

Current problem:

- Settings has a special command/search header, but Files and Process do not have equivalent framing.
- Presets are near the top, while current-settings import/export is in the footer.
- This makes it unclear whether presets are the active settings, a subset of settings, or a separate export system.

Current implementation model:

- Active settings are the current processing configuration.
- Active settings auto-save in browser local storage.
- A preset is a named snapshot of active settings.
- Loading a preset copies that preset into active settings.
- Export settings exports only the current active settings.
- Import settings replaces active settings.
- Export presets exports the saved preset library.
- Import presets appends presets to the saved preset library.

### Files Tab

Current structure:

- Header: `Files`
- Drop zone with hidden file input and `Choose files` button.
- Per-file rows showing:
  - file name
  - size
  - row count
  - column count
  - status pill
  - one timezone name, or `N timezones`
  - warnings text

Current problems:

- Multiple timezones are summarized as `N timezones` instead of listing each timezone.
- Duplicate timestamps are treated as warnings even when the selected settings will correct them.
- File rows are cards, not a real table of processing-relevant statistics.
- The file-level display does not clearly say what will happen later during timezone filtering/conversion.

### Process Tab

Current structure:

- Header with queued file count, estimated input rows, and rough ETA.
- `Process files` button.
- Synced performance controls:
  - `Parallel processing`
  - `Max parallel workers`
- Readiness warning text if any selected file has warnings.
- Before processing: list of queued files with `Ready` and `0%`.
- During processing: progress rows by file and stage.
- After processing: `ResultPanel`.

Current problems:

- Timezone plan is not explicit before running.
- It does not tell the user whether rows will be filtered out or converted.
- It does not show per-file timezone outcomes in a user-readable way.

### Results Panel

Current structure:

- Results header with batch summary.
- Download buttons:
  - `Download all ZIP`
  - `App ZIP`
  - `Screen ZIP`
  - `Copy report`
- Result warnings block.
- Aggregate stat grid:
  - original rows
  - processed rows
  - app rows
  - screen rows
- Collapsed `File counts` table:
  - input file
  - final timezone
  - original rows
  - processed rows
  - app rows
  - screen rows
- Preview section:
  - App/Screen buttons
  - table preview

Current problems:

- Preview only shows the first available app output or first available screen output.
- There is no file selector for preview.
- For multi-file processing, the preview is misleading.
- The file counts table is collapsed and too thin to serve as the main result surface.
- Results do not show enough per-file processing facts:
  - rows removed by timezone handling
  - whether timezone handling filtered or converted
  - duplicate timestamps corrected
  - output filenames
  - output row counts per output
  - support-file effects

### Footer

Current footer contains:

- reset defaults
- settings import/export
- collapsible app info

Current problem:

- These are not footer concepts.
- Reset/import/export belong in the Settings system.
- Version/build/app info should be shown in a visible About/System area or compact header metadata.

## Specific Product Issues To Fix Next

### Tabs

- Remove tab subtitles/meta text.
- Keep tabs compact, centered, and horizontally aligned.
- Avoid vertical stacking unless the viewport truly requires it.

### Settings And Presets System

Replace the split model with one coherent settings management area:

- `Current settings`
  - Used for the next run.
  - Auto-saved in this browser.
  - Can be exported/imported as one settings file.
- `Preset library`
  - Saved named snapshots of current settings.
  - Loading a preset replaces current settings.
  - Saving a preset stores the current settings under a name.
  - Preset library can be exported/imported separately.
- Put all reset/import/export/save/load controls together in Settings.
- Remove settings persistence controls from the footer.

### Support File Wording

Rename keep-awake wording:

- Current wording: `Keep-awake apps file`
- Better wording: `Screen-awake apps file`
- Better description: apps in this file are treated as apps that can keep the screen on during screen-usage detection.

Reason:

- The current phrase makes it sound like the apps are being kept awake.
- The actual meaning is that these apps keep the screen awake.

### File Validation

- Do not show duplicate timestamps as a readiness warning when duplicate correction is enabled.
- Treat duplicate timestamps as an informational metric.
- Move the meaningful metric to Results:
  - duplicate timestamp groups found
  - duplicate timestamps corrected
  - rows affected

### Timezone Visibility

Files tab should show all timezones per file, not just `N timezones`.

Process/Results should show:

- input timezones
- timezone handling mode
- target timezone
- action taken:
  - filtered to selected timezone
  - converted to selected timezone
  - filtered to primary timezone
  - converted to primary timezone
- rows before timezone handling
- rows after timezone handling
- rows removed by timezone filtering, if any

### Results Table

Make a real results table the main post-processing view.

Recommended columns:

- input file
- status
- input rows
- processed rows
- app rows
- screen rows
- input timezones
- timezone action
- final timezone
- duplicate timestamps corrected
- warnings
- outputs

Keep aggregate stats above the table, but do not hide the table in a collapsed details element.

### Preview

Either remove preview entirely, or make it explicit and selectable.

Recommended for the next pass:

- remove preview by default
- keep downloads and results table as the primary output surface

If preview is kept later, it must have:

- selected input file
- selected output type
- selected output filename

### Study/Admin Metadata

There is a likely mismatch:

- `studyName` exists in Settings.
- Its tooltip says it writes metadata into generated CSVs.
- The current output path appears to keep `study_id` from the input row rather than applying `options.studyName`.

Next engineer should decide the intended semantics:

- If `studyName` should override output `study_id`, wire it into the pipeline and test it.
- If it is not supposed to override output CSVs, rename/reword the setting and tooltip.
